# TraceLens for TDP · 威胁透镜

**面向 ThreatBook TDP 的 AI 威胁调查工作台，让每个判断都有证据可循。**

> 独立开发的非官方项目，不代表 ThreatBook 官方产品，也未声明获得其背书。ThreatBook 与 TDP 名称仅用于说明兼容目标。

TraceLens 围绕一个问题组织调查：**“这台主机是否存在需要进一步核实的失陷迹象？”**
从告警主机进入调查，关联时间范围内的真实日志，把原始证据、规则判断、证据缺口和人工记录放在同一份可复查的档案里。

## 当前能力 · v0.2.0

- **无账号案例演练**：无需 TDP 地址或 Key，显式进入合成攻击案例，体验完整调查流程。
- **真实数据源**：TDP HTTPS 连接、API Key / Secret 签名鉴权、连接诊断。
- **调查总览**：安全态势、告警主机查询，时间 / 关键词 / 严重程度筛选和分页。
- **目标调查**：IPv4 / IPv6 与完整域名精确查询、时间窗口、源/目的资产快照。
- **主机角色**：区分通信源/目的与原始 attacker/victim 安全角色；目标发起的成功攻击不会被当成目标遭到入侵。角色缺失或冲突保留为未知。
- **告警归并**：按规则、类型、通信对象、角色、结果与节点归并，展示记录数、首次/最后发现；可展开所有原始引用。
- **关联调查**：从 IP、域名或 IOC 继续查询，沿用来源平台与时间窗口，双向保存来源档案、快照 ID 和证据引用。
- **来源追溯**：每条记录保留平台、节点、原始 ID、采集时间、查询窗口和规范化原始 JSON 的 SHA-256；哈希不是数字签名或完整取证保全链。
- **证据时间线**：按时间排序、方向和关键词筛选、稳定的快照内证据编号、原始记录查看。
- **规则辅助判断**：目标受害成功要求明确 victim 字段；远控连接要求目标是通信源。不会从方向推断攻击角色。
- **通信关系图**：根据当前快照绘制直接通信对端，点击地址查看引用证据，避免把连线误作已证实攻击链。
- **调查留档**：本地 SQLite、人工备注、调查状态、历史快照、Markdown 报告导出。
- **后续复查**：支持普通后续查询，也可绑定用户声明的实际处置时间、动作、范围与执行依据，选择基准快照检查同类行为复发与通信对象变化。不会自动执行处置。
- **可选 AI**：用户配置兼容 Chat Completions 的模型服务；先预览证据摘要和目的地址，再明确确认发送。模型必须输出结论、支持证据、反对证据、缺失信息、下一步；结构或引用校验失败时拒绝保存。通过校验仍不表示语义正确。

**这是可运行的本机单用户首版**。尚未提供团队登录、后台定时复查、自动封禁或 MCP 服务端。多人部署和生产服务加固属于后续范围。

## 快速开始

需要 Python 3.9+。从源码启动不需要安装第三方运行依赖，不需要 Node.js 构建。

```bash
git clone https://github.com/GuoyuanSen/tracelens-tdp.git
cd tracelens-tdp
python3 run.py
```

不使用 Git 也可以在 GitHub 点击 **Code → Download ZIP**，解压后启动：

- macOS：双击 `start.command`；如果解压后的执行权限丢失，在终端运行 `sh start.command`。
- Windows：双击 `start.bat`；需要先安装 Python 3.9+。
- Linux 或终端：在项目目录运行 `python3 run.py`。

启动后用浏览器打开 **http://127.0.0.1:8765**。保持启动终端运行，关闭服务后页面将无法查询。首版是本机网页工具，不是已打包的桌面安装程序。

没有 TDP 环境？点击首页 **使用演练数据 → 进入演练**，无需填写任何地址或 Key。页面与导出报告会明确标识合成数据，演练不发出 TDP 或模型请求。[案例说明与练习任务](docs/demo-case.md)。

连接真实 TDP：

1. 进入 **连接设置**，填写自己的 TDP HTTPS 地址、API Key 和 Secret。
2. 保存后点击 **验证已保存连接**，确认网络与签名鉴权正常。
3. 从 **调查总览** 选择主机，或点击 **发起主机调查** 输入 IP。
4. 查看 **调查判断 / 证据时间线**，打开具体证据核查原始记录。
5. 在 **人工记录** 中记录核查与处置时间。积累后续数据后使用 **后续窗口复查**。
6. 按需导出最新快照报告。报告包含调查数据，请妥善保存。

端口被占用时：

```bash
python3 run.py --port 8766
```

## 凭据与数据

**所有地址和密钥由使用者自行配置。仓库不提供任何真实 API Key、Secret、内部测试地址或真实告警数据。**

默认本机数据目录：`~/.local/share/tracelens-tdp/`，包含：

| 文件 | 内容 |
| --- | --- |
| `config.json` | 本地连接和模型配置；保存的密钥不回显给浏览器 |
| `cases.sqlite3` | 调查证据、快照、备注与分析 |

数据目录权限为 `0700`，配置与数据库为 `0600`（POSIX 系统）。密钥为本地文件存储，**不是加密保险库**；Windows 用户应自行保障数据目录 ACL。数据不在源码目录中；`.gitignore` 也排除了环境文件、密钥、数据库和导出目录。

也可使用进程环境变量；环境变量优先于设置页，对应字段会显示为只读。`.env.example` 是空白模板，程序**不自动加载 `.env`**。如需使用，在可信的本地 shell 中加载后再启动：

```bash
cp .env.example .env
# 编辑 .env，填写自己的配置，然后：
set -a
. ./.env
set +a
python3 run.py
```

不使用的环境变量应从 `.env` 删除，避免空值覆盖设置页。不要把环境文件提交到 Git。

| 环境变量 | 用途 |
| --- | --- |
| `TRACELENS_TDP_URL` | TDP HTTPS 根地址，无页面路径 |
| `TRACELENS_TDP_KEY` | 请求方 API Key |
| `TRACELENS_TDP_SECRET` | 请求签名 Secret |
| `TRACELENS_AI_URL` | 模型基础地址，例如 `https://model.example.com/v1` |
| `TRACELENS_AI_MODEL` | 服务商提供的模型 ID |
| `TRACELENS_AI_KEY` | 可选模型密钥 |
| `TRACELENS_CA_FILE` | 内部 CA 证书文件路径 |
| `TRACELENS_DATA_DIR` | 自定义本地数据目录 |

TDP 与模型连接始终校验 TLS 证书，不提供跳过校验的选项。内部 CA 使用 `TRACELENS_CA_FILE` 配置。默认网络行为遵循 Python 的系统代理环境变量。

## AI 数据边界

默认不调用模型。未配置模型时，真实查询、规则判断和留档仍可独立工作。

点击“预览数据并分析”会展示目的地址及即将发送的内容，包括目标 IP、时间、威胁名称、源/目的 IP、IOC 等，最多 100 条证据摘要。**使用云端模型时，这些内容会传给该服务商。** 用户每次确认后才发送；TDP 凭据、原始日志载荷、资产负责人字段和人工备注不包含在 AI 请求中。

AI 文本是辅助建议，不是已验证事实。没有支持引用的肯定结论、不完整结构或不存在的引用会被拒绝保存；引用存在也不代表模型解释必然正确。模型不会获得执行处置的工具。

接口格式参考 [Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat)。其他兼容服务需自行确认其模型和协议支持情况。

## 结果覆盖与兼容性

当前适配 TDP 3.3.13 开放 API：

| 功能 | 方法与路径 |
| --- | --- |
| 安全态势 | `POST /api/v1/dashboard/security` |
| 告警主机 | `POST /api/v1/host/getFallHostSumList` |
| 主机日志 | `POST /api/v1/log/searchBySql` |

- 单次时间窗口上限 31 天；建议从 24 小时开始。
- 主机列表每页 20 条。日志接口可能只返回部分记录；当前版本不伪造分页参数，也不宣称拿到了全部数据。
- 每个调查快照最多保留 500 条有效记录，超过上限、总量未知、总量大于返回量或记录被过滤时，明确提示覆盖不完整。
- 日志查询可能缺少终端证据、缺少采集或存在权限限制。**没查到不等于没有风险。**
- 原始记录的“攻击成功”来自 TDP 字段；只有目标同时被标记为 victim 才计入“目标受害且成功”。实际影响仍需终端取证和业务背景核实。
- 普通复查必须是后续窗口；绑定处置的复查从处置时间后开始，仅使用选定基准中早于处置的记录作比较，且不能更换来源平台。窗口长度与数据覆盖可能不同，因此不直接据事件数下降宣布处置有效。
- 所有 TDP 操作均为查询，不修改远端策略或处置状态。
- 没有实时环境时会显示配置或请求错误，不会自动用假数据替代。案例演练必须显式选择，使用文档保留网段的合成数据；单元测试使用独立合成夹具。

## 本地开发与测试

```bash
python3 -m unittest discover -s tests -v
node --input-type=module --check < tracelens/static/app.js
```

测试覆盖签名、目标角色、归并边界、IP/域名查询、双向关联、数据覆盖、来源哈希、结构化 AI 输出、处置复查、历史档案兼容、并发存档、凭据隐藏与跨站防护。测试不连接真实 TDP 或模型服务。

```text
tracelens/
  server.py          本机 HTTP 服务与业务接口
  demo.py            显式选择的合成案例演练
  tdp.py             只读 TDP 适配、签名与错误处理
  investigation.py   证据归一化、复查和报告
  evidence.py        角色识别、归并、来源追溯与处置对比
  storage.py         本机配置与 SQLite 存储
  ai.py              可选模型分析与证据摘要
  static/            网页界面，无远端 CDN 依赖
```

详细设计见 [架构与边界](docs/architecture.md)。

## v0.2 调查边界

- 域名仅精确匹配日志 `data` / `threat.ioc` 字段，不进行社区情报查询、子域名模糊检索或 URL 子串查询。
- 覆盖条在调查页所有页签显示：查询窗口、返回量、保留量、总量、去重数量、来源与采集时间。返回完整不代表环境采集完整。
- 历史 v0.1 档案读取时补充角色与归并视图，保留原始证据和引用；历史来源时间标明来自快照保存时间，不伪装成精确采集时间。旧 AI 结论显示需重新核查提示。
- 处置记录由用户声明。复查时匹配相同规则、类型、方向、角色、结果和节点，区分原通信对象与新对象；不宣称这些记录必定属于同一攻击者。
- 三类演练分别覆盖异常外连、授权运维和证据不足；授权背景是案例资料，不是自动加白规则。

未保存演练时间锚点的早期档案保留查看与导出；继续查询需新建演练，避免用新的时间锚点伪造历史连续性。
