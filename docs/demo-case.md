# 案例演练：一台终端的异常外连

所有数据为人工构造，使用 RFC 5737 文档保留 IP 网段和 example.com 子域名，不指向真实企业、设备或攻击基础设施。

## 如何体验

启动工作台后，点击首页“使用演练数据”下的“进入演练”。也可从连接设置进入。演练不要求 TDP 地址或 API Key，不发出 TDP 网络请求，不调用模型服务。切换回真实环境不会覆盖已保存的真实凭据。

演练记录在进程启动时生成固定时间锚点。默认过去 24 小时可看到全部案例，修改时间窗口会实际过滤记录。新调查在重启后使用新的演练锚点；已存档演练会保留原锚点，后续复查沿用原案例时间。

## 案例线索

| 对象 | 角色 |
| --- | --- |
| `192.0.2.10` | 财务终端，主要调查对象 |
| `192.0.2.20` | 文件服务器，关联调查对象 |
| `192.0.2.30` | 运维终端，低风险对照对象 |

建议先调查财务终端，再用相同时间范围调查文件服务器。

## 练习任务

1. 从主机总览进入财务终端调查，找到钓鱼访问、文件下载、远控连接和横向访问的时间顺序。
2. 检查哪些记录被标记为成功，哪些仅为未知结果。
3. 对“文件服务器也已失陷”这一假设，列出证据缺口。
4. 在人工记录中写下下一步核查动作，并保存。
5. 查看原始记录，核对模型之外的确定性字段。
6. 在后续窗口执行复查，观察“未发现记录”与“风险已消除”的区别。

## 预设事实与边界

- 财务终端存在远控类事件，连接字段为真；这支持优先复核，但没有终端进程或文件执行证据。
- 横向访问被标记为成功，但这一标签不等于证明攻击链完整成立。
- 文件服务器只有可疑外连尝试且连接未确认，不能据此断言失陷。
- 运维终端的扫描记录标记为失败；业务用途仍待确认。
- 案例故意不提供“所有主机均已失陷”的标准答案，练习目标是区分事实、假设与缺口。

这是一组交互演练数据，不是测试环境抓取的数据，也不是自动伪造的产品成果。
